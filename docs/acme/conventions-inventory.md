# Acme conventions inventory

Rows whose source is SYNTH are lab policies. They are not requirements in the scikit-image contributor documentation.

| Convention | Source | Enforcement |
|---|---|---|
| Document public functions using NumPy-style docstrings. | doc/source/development/guidelines.md — docstring guidance | lint/test |
| Refer to dimensions as plane, row, and column, rather than x, y, and z. | doc/source/development/guidelines.md — dimension terminology | human review |
| Document array parameters as image : ndarray of shape (M, N); refer to M and N later when needed. | doc/source/development/guidelines.md — array parameter documentation | human review |
| Use NumPy types such as np.uint8 instead of strings such as "uint8". | doc/source/development/guidelines.md — NumPy data types | human review |
| Use relative imports inside the library, e.g. from .._shared import xyz rather than from _skimage2._shared import xyz. | doc/source/development/guidelines.md — module imports | human review |
| Keep strict warning checks enabled during testing; warnings are errors by default. | doc/source/development/testing.md — Warnings during testing phase | lint/test |
| Use FutureWarning to announce public API changes that require a deprecation warning. | doc/source/development/deprecations.md — Raising Warnings | human review |
| Use deprecate_parameter or deprecate_func where appropriate when removing parameters or functions. | doc/source/development/deprecations.md — Deprecating Keywords and Functions | human review |
| Accept the documented image dtypes and convert them with `img_as_float`, `img_as_ubyte`, `img_as_uint`, or `img_as_int`, which rescale integer intensities into the user-guide ranges. Do not use `astype` on an image. `img_as_float` keeps floating-point precision and does not rescale float inputs. Signed-to-unsigned conversion clips negative values to 0. The output dtype may be whichever is most efficient. Uncertain: the style guide says functions should support every input dtype, while the user guide allows a documented subset (convert, warn if a copy is made, and note the requirement in the docstring) and says 64-bit integer images are unsupported except for exceptions it does not list. `preserve_range` applies only where a function already has that argument. | doc/source/development/guidelines.md — Stylistic Guidelines; doc/source/user_guide/data_types.rst — Image data types and what they mean, Input types, Output types, Note about negative values | human review |
| Use a deprecation cycle when renaming keywords, reordering arguments or keywords, adding arguments, changing a function's name or location, or changing a default. A cycle is not required to add a function, to add a keyword at the end of a signature, or to fix incorrect behavior. Put the removal on `TODO.txt` under the target version. Uncertain: warnings are "typically" kept for two releases, but the worked example lands the change in N+3 and says that three-release schedule is not strict. That example also says to edit `doc/release/release_dev.rst` under a deprecations heading; that path is not in the tree and conflicts with the release-note row. | doc/source/development/deprecations.md — Deprecation cycle (advanced); CONTRIBUTING.md — Document changes | human review |
| Add tests for behavior changes under `tests/`. Docstring examples in `src/` are tested too. Coverage should ideally be 100% statement coverage, and review expects each added line to be covered. Uncertain: the testing guide's examples name `tests/skimage/` only. SKIP 4 proposes duplicating the suite for `_skimage2` and adjusting it, but that SKIP is Draft (not in effect) and does not name `tests/skimage2/`. | doc/source/development/testing.md — Testing, Test coverage; doc/source/development/guidelines.md — Guidelines; doc/source/development/core_developer.md — Reviewing; doc/source/skips/4-transition-to-v2.rst — Test coverage of both APIs (status Draft) | human review |
| The test suite must pass before a pull request is merged. Pull-request CI runs only modified subpackages; the full suite runs on pushes to `main` and on merge-queue entries. Add the `run-all-tests` label when the change is not confined to one subpackage, such as test infrastructure. | doc/source/development/testing.md — Testing, CI runs only modified tests on pull requests; CONTRIBUTING.md — Review process | CI gate |
| For new functionality, add a gallery example that explains the feature, not only the call. Examples live in `doc/examples` and are built with Sphinx-Gallery. Figure width should be at most 8 inches. A gallery example is not documented as a requirement for changes that are not new functionality. | doc/source/development/guidelines.md — Guidelines; doc/source/development/building_docs.md — Gallery; doc/source/development/core_developer.md — Reviewing | human review |
| Let changelist form the release note from the pull-request title and GitHub labels. For a more complex change, describe it in a `release-note` block in the pull-request description. The pull-request template marks that block optional. A deprecation still needs a `TODO.txt` reminder. Uncertain: the docs do not say which labels select the section, or that they are the category labels CI waits on. Authors are not told to edit `doc/source/release_notes/` by hand. | CONTRIBUTING.md — Document changes; .github/PULL_REQUEST_TEMPLATE.md — Release note (optional) | human review |
| New runtime dependencies require platform approval. | SYNTH — not stated in the contributor documentation | human review |
| Unit tests must not use the network. | SYNTH — not stated in the contributor documentation | lint/test |
| Pull-request titles start with a ticket ID such as `ACME-123:`. | SYNTH — not stated in the contributor documentation. The contributor guide asks only for a concise, descriptive title. | CI gate |
